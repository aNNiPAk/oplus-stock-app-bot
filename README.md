# OPlus Stock App Bot

Обновления семи стоковых приложений OPlus для Obtainium: календарь, заметки, диктофон, калькулятор, погода, часы и сообщения. Сообщения — OPlus `com.android.mms`; Google Messages не публикуются.

## Общий проход

Workflow **Update stock suite** (`suite.yml`) проверяет пул свежих прошивок OPPO, OnePlus и Realme на Android 16. Каждый нужный раздел донора извлекается один раз, затем из него собираются сразу все семь приложений. Доноры выбираются по свежести сборок с квотами по брендам; региональные дубли одной глобальной ветки исключаются. По умолчанию максимум шесть доноров.

Бот сравнивает фактический Android `versionCode` отдельно для каждого приложения:

- APK с русскими ресурсами — основной канал.
- Более свежий APK без русского, но с английским или неопределённым языком — experimental.
- APK с явно указанными языками, среди которых нет ни русского, ни английского, отклоняется.
- Overlays не делают базовый APK русским. В общем проходе дополнительные разделы ради overlays не скачиваются.

Подпись APK проверяется криптографически; сертификат записывается в отчёт и не сравнивается с сертификатом предыдущего релиза. APK не изменяется и не переподписывается. Наличие русского и корректная подпись не гарантируют работу на каждом телефоне: возможны зависимости от библиотек и сервисов прошивки.

## Передача APK каналам

Центральный бот публикует неизменяемый prerelease `suite-<hash>` с manifest и выбранными APK. Неполная загрузка остаётся draft. Если набор версий и хешей не изменился, новый набор не публикуется.

Канальные репозитории используют reusable workflow `consume-suite.yml`: скачивают только нужные новые APK, заново проверяют хеш, подпись, package, versionCode и язык, затем публикуют собственным штатным GitHub Actions токеном. Общий PAT не требуется.

Основной APK становится Latest в канале. Experimental публикуется с `--prerelease --latest=false` и никогда не заменяет Latest. Понижение versionCode не выполняется.

## Кеш и ошибки

Успешно прочитанные OTA кешируются по идентификатору, устройству, сборке и конфигурации. Кеш содержит APK и публичные метаданные, но не подписанные URL; хеши и подписи проверяются при повторном использовании. Изменения кода/конфигурации сбрасывают кеш. Доноры с ошибкой чтения не кешируются как пустые.

HTTP Range использует ограниченный кеш 32 MiB, блоками по 4 MiB. При 401/403 ссылка обновляется и повторяется текущий запрос, без перезапуска извлечения раздела. Проверки HTTP диапазонов, размера OTA, хешей операций и образов сохраняются. Извлечение отдельного раздела ограничено десятью минутами.

Обычный проход ограничен разделами из `package_partitions` (`my_product` и `my_stock`). Если приложение отсутствует, бот не скачивает автоматически весь `system`. Ручной параметр `deep_scan` включает расширенный поиск; он заметно медленнее. Ошибка чтения раздела отражается отдельно от отсутствия приложения.

Отчёт каждого общего прохода доступен как Actions artifact `stock-suite-report`. В нём указаны доноры, ошибки и выбор по приложениям. Если для любого из семи приложений нет допустимого APK, новый набор не публикуется.

## Запуски

- Центральный проход: каждые шесть часов, либо Actions → Update stock suite → Run workflow.
- Ручной запуск по умолчанию dry-run: весь сбор и проверка без публикации набора. Для живой публикации снимите dry-run.
- Каналы проверяют опубликованные наборы по собственному расписанию или вручную. Центральный набор должен успеть завершиться.
- Unit tests выполняются автоматически на push/PR. Тяжёлые legacy/model-only и отдельные multi-donor проверки оставлены только для ручного запуска и больше не вызываются при изменении тестов.

`oplus-compat` из исходного архива — необязательный прототип наблюдения, без готовых патчей совместимости. Общий updater от него не зависит.
